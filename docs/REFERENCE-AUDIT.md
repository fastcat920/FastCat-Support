核对日期：2026-10-27（Asia/Shanghai）。原审计版本：0.8.0；当前实施版本：0.23.0。

## 0.23.0 访客资料、回执与界面统一

- 首次咨询只需邮箱，系统以邮箱作为访客名称；空邮箱和无效邮箱会被拒绝。历史访客不重建、不强制补填。邮箱是访客提供的信息，不用于验证身份或合并访客。
- 网页嵌入支持 `data-email` 和 `data-visitor`；Flutter SDK 0.15.0 支持在 `start` 和 `updateProfile` 中传入资料。资料按访客会话保存，更新需当前会话凭据，未授权请求不能修改其他访客。支持联系信息、设备、平台及受限自定义字段。
- 客服资料区按联系信息、用户资料和自定义信息分组，窄屏资料窗口也能查看；现有备注、负责人和优先级保留。统一常用表单、页面间距和聊天资料排版；没有声称全部页面已与参考项目逐像素一致。
- 网页访客和客服端使用时间后的 ✓ / ✓✓ 表示已发送和已读，Flutter 聊天也使用相同规则。送达仍保留在协议中，但界面不再单独显示文字。
- 通用设置和平台外观的主题色控件显示色块及十六进制色值。移除标签管理菜单、接口及会话的标签筛选和编辑；历史标签表保留，不删除原记录。
- Node 135 项测试、Flutter 15 项测试与静态检查通过。浏览器验证邮箱创建会话、嵌入页面资料传递及显示、双端回执、色块预览、核心工作台页面；真实供应商未调用。旧 SDK 仅传姓名的创建会话调用需升级并传邮箱。

## 0.22.0 网页客服入口图标与本地预览

- 网页入口改为圆形图标，默认使用项目 F 图标；展开后原位置显示关闭图标，聊天窗口独立定位，避免窗口打开时入口移动。支持四个悬浮位置、键盘操作和中英文无障碍名称；主题色继续使用后台配置。
- 平台 → 组件外观支持上传 PNG、JPEG 或 WebP 图标，也可填写 HTTPS 图片地址或恢复默认图标。上传会裁切为正方形；无效图片或地址会被拒绝，图片加载失败时回退到默认图标。
- JS 响应显式声明 UTF-8，嵌入脚本使用可跨宿主字符集解析的转义字符串并设置重新验证缓存。嵌入区域隔离宿主页面样式；加载配置失败时仍可打开错误提示并重试。
- 网页平台可单独开启本地文件预览：允许 `Origin: null` 的请求，并为该平台的访客页面开放 `file:` 嵌入。此选项也允许其他来源为 `null` 的页面访问该公开平台，建议只在本地测试时启用。正式网页应填写明确的允许来源；HTTPS 网页需要使用 HTTPS 客服服务。
- 133 项测试及格式检查通过；隔离浏览器验证了默认图标、已上传图标、打开与关闭保持同一位置、配置失败时可重试，以及后台保存配置。API 验证了默认拒绝、开启本地预览后允许 `Origin: null`、图片格式校验和关闭后重新拒绝。
- 自动浏览器安全策略不允许打开 `file://` 页面，因此本地文件在真实浏览器中的完整嵌入行为仍需用户手动刷新确认。图片文件选择器的交互未自动化，上传后的图片保存与渲染已通过 API 和浏览器验证。

## 0.21.0 语言、主题与会话流转

- 设置 → 通用新增简体中文 / English / 跟随浏览器，账号独立保存语言、明暗模式和主题色。导航、设置、收件箱、平台及模型配置等内置界面支持中英切换；客户消息、知识内容、模型生成正文与自定义名称不做机器翻译。
- 网页组件默认跟随宿主 `html.lang`、`data-theme` / 明暗主题类及 `prefers-color-scheme`；只同步语言与明暗模式，主题色始终使用后台平台配置，不读取或覆盖宿主主题色。嵌入脚本支持 `data-language`、`data-theme`。宿主变化可实时同步；消息桥接只接收父窗口、来源校验通过的外观消息。平台可固定语言、明暗模式和主题色；自定义品牌配置继续保留。
- Flutter SDK 0.14.0 默认跟随宿主 Localizations 与 ThemeData，保留宿主明暗模式，主题色从后台平台配置读取；可通过 locale 固定语言。结束会话后仍可在原窗口发送。SDK 下载包同步更新。
- 状态统一显示在线 / 忙碌 / 离线，仅在线且未满容量的启用成员可自动接收转人工。兼容原有 API 状态值 available / away / offline，不改写现有账号与接待配置。
- 移除创建团队入口与创建接口、独立接待团队标签。成员管理统一展示并编辑在线状态、工作量及同时处理容量；工作时间保留独立子标签。历史团队数据与会话关联保留。
- 移除平台归档、恢复界面与接口。已有归档记录升级为可管理的停用平台，保留公开标识、访客与历史消息，不自动启用。
- 当前会话完成后按队列顺序跳转下一条未结束会话，支持状态下拉、结束按钮和批量处理；其他客服完成当前会话时也会前进。没有下一条时显示空白选择状态。
- 访客的新消息可原地重新打开已结束会话，清除上一轮负责人、人工请求与等待状态，并按平台策略恢复 AI；纯人工平台及非工作时间策略保留。文本及附件重试去重在重开前执行，旧消息重试和无效消息不会重开；附件仍按现有策略转人工处理。

验证：132 项 Node 测试通过；Flutter analyze 无问题、13 项测试通过；格式检查通过。隔离浏览器已验证英文偏好保存、宿主中英文及深色主题实时同步、忙碌状态 / 容量保存、结束后自动选择下一条及访客继续发送后恢复 AI。AI 使用本地协议模拟，未调用生产模型。

## 0.19.0 转人工分配修复

- 转人工立即分配给已启用、可接待且未达容量的客服，优先当前未结束会话较少者；有接待团队时仅在该团队内选择。已分配会话及客服主动接管保持原归属。
- 无合适客服时仅将明确的转人工请求标记为等待分配，每秒重试；恢复可接待或释放容量后可领取。手动取消分配不会再次被自动领取；普通未分配会话不参与该队列。
- 升级仅将旧版明确请求人工、发送附件转人工或 AI 失败转人工的未分配会话加入补分配队列。保留已移除的全局自动接待模块关闭状态。
- 工作时间继续约束平台 AI；人工分配按客服实际可接待状态与容量判断，不阻止非工作时间在线人工客服接待。

119 项测试通过，包括容量、停用/离线、团队范围、重复请求、手动取消和升级补分配。隔离用户端已验证点击“联系人工”后显示“人工客服接待中”，会话进入客服负责队列。
