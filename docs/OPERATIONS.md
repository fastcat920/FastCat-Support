# 运行管理与可靠性

本版本保持单 Node 进程、SQLite WAL 的部署方式，不支持直接开启多实例。所有新管理接口必须登录，`/api/operations/*` 仅管理员可访问。

## 后台入口

设置 → **运行状态、备份恢复、服务质量、知识改进**。

- 运行状态：版本、Git commit、端口、数据库可写状态、推送配置、积压与失败原因、客服在线连接。
- 会话顶部显示未分配原因、排队位置和等待时间。新排队记录按本轮入队时间排序；位置在同一团队队列中计算。历史无入队时间的记录回退至会话创建／首条消息时间。
- 会话 → **交接与结果**：已知设备、最近问题、有效授权、诊断和修复状态；可登记解决结果或提交知识改进。
- 知识改进必须由管理员编辑并审核，才写入默认知识库。重复审批不会重复创建条目。
- 服务质量可选 7／30／90 天。解决率只使用客服手工登记样本；首次回复（AI／人工）及首次人工回复分别统计本期新会话；AI 转人工率的分母为本期新建且有 AI 运行记录的会话，分子为其中 AI 接待之后发生人工转接的会话，排除纯自动分配。人工接待事件另按本期事件去重，不直接与新会话数量相除。AI 费用按币种分别汇总，缺失价格的请求不冒充零费用。

## 消息与推送

消息写入时，SQLite trigger 在同一事务保存推送事件。派发时，已观察标记和设备任务在同一 savepoint 提交。进程重启会继续处理未完成事件；首次升级不追发全部历史。

未配置 APNs 不再阻塞 FCM。已有发送前的已读、前台、账户、凭据和设备有效性检查保留。外部推送服务不提供本项目可控的精确一次保证：发送成功后、写回结果前宕机仍可能导致重复通知。消息 ID 用于客户端去重。

## 在线与分配

接待状态（在线／忙碌／离线）与实际连接分别判断。登录、已认证请求和存活的客服 SSE 连接维护 75 秒有效的在线租约，退出登录立即使该会话租约失效。网页和客服 APP 可调用 `POST /api/presence/heartbeat`（建议每 25 秒）明确续期。

人工及人工优先模式复用分配规则：工作时间内、有效在线、未满容量、负载最低。无人可接待时保留排队；人工优先模式仍保留超时 AI 兜底。没有访客消息的空会话不占接待容量。

## 限流与配额

- API：默认每 IP 每分钟 1200 次，可用 `API_RATE_PER_MINUTE` 调整。默认使用真实 socket 地址。宝塔本机 Nginx 反代建议配置 `TRUST_PROXY=loopback`：仅信任本机代理写入的 X-Forwarded-For 最后一项。代理必须覆盖或追加真实远端地址，不可原样透传伪造值。远程连接的伪造请求头不受信任；还可在 Nginx 设置限流。未设置时，同一反向代理后的请求可能共享 IP 限额。
- 登录／初始化：每 IP 15 分钟 20 次；创建会话每分钟 60 次；消息和附件提交每个凭据每分钟 120 次。
- 同一访客会话、同一客服用户最多各 5 条 SSE 连接。
- 每个访客或客服每日默认上传 100 MiB（包括重试传入的文件），可用 `UPLOAD_DAILY_MB` 调整；额度持久化。
- 自动客服全局等待队列默认最多 100 个会话，可用 `AI_QUEUE_LIMIT` 调整。超出时转人工。

限流返回 429、错误代码与请求编号；窗口限流附带 Retry-After。当前内存频率限制依赖单实例，上传日配额存于数据库。

## 健康检查与日志

- `GET /api/health/live`：进程响应。
- `GET /api/health/ready`：数据库写入探针、版本、启动时 Git revision。
- 更新脚本会校验就绪状态和预期 revision，避免误把旧进程判定为新版本。
- 请求响应包含 X-Request-ID；错误响应包含 requestId 和 code。日志采用 JSON，不记录请求正文、凭据、Cookie 或完整 URL。内部异常仅向客户端返回通用错误，服务端记录类型、代码和调用位置。
- 收到 SIGTERM／SIGINT 时停止接待、终止 AI 和 SSE，关闭服务。设备修复的结果不确定时仍须复查，不能盲目自动重试。

## 备份、验证和恢复

每分钟检查调度条件，每 24 小时创建一致性 SQLite 备份。第一次启动后约一分钟执行首次备份。默认目录是数据库旁的 `backups/`，权限 0700；可用 `BACKUP_DIR` 指定专用私有目录，禁止放入公开静态目录。默认保留 7 份成功快照，可用 `BACKUP_KEEP` 调整。失败保留运行记录，下次自动尝试间隔至少一小时。

备份包含数据库、存在的 `<DB_PATH>.key`、环境配置中的主密钥、身份签名密钥和 APNs／FCM 凭据文件。清单记录 SHA-256；创建时执行 quick_check 和 foreign_key_check，重新打开校验核心表。文件权限 0600。此校验检测损坏，不是防恶意篡改的签名。

**必须另行设置异机安全保存。** 本项目不会擅自配置第三方存储或发送密钥。备份界面会展示失败和校验结果，管理员网页登录及停留前台时每分钟检查最近备份失败并提示（不替代站外运维告警）；文件校验不替代定期整机恢复演练。

```sh
node scripts/restore-backup.mjs /私有备份目录/backup-编号 /全新的恢复目录
```

工具先校验，再复制到全新目录；已有目标目录会被拒绝，不覆盖运行中的数据库。恢复到新目录后：

1. 停止服务。
2. 配置 DB_PATH 指向恢复目录的 support.db，保持 support.db.key 对应关系。
3. 若使用 FC_MASTER_KEY／VISITOR_IDENTITY_SECRET，恢复相应环境变量；推送密钥恢复到原位置或更新路径。
4. 启动服务，检查就绪接口、模型解密、会话和推送配置。

代码更新不会自动回退数据库。数据库恢复必须由运维明确执行。

## 安全的用户与设备会话复用

旧接入和本地凭据恢复继续可用。跨本地缓存丢失的服务端复用，必须由**宿主后端**签发短期 HS256 JWT。不能把签名密钥放进网页或 APP。

客服后端与宿主后端配置同一 `VISITOR_IDENTITY_SECRET`，至少 32 字节。声明示例：

```json
{
  "sub": "业务用户ID",
  "deviceId": "持久化安装ID至少16位",
  "appKey": "当前接入Key",
  "email": "user@example.com",
  "iat": 1790000000,
  "exp": 1790000300
}
```

JWT 头使用 alg=HS256；建议 5 分钟，最大 1 小时。deviceId 必须是宿主后端与该账户绑定的安装标识，不要接受未校验的任意用户／设备声明。宿主应验证登录与设备归属后签发。

`POST /api/widget/start?appKey=...` 传 email、profile、deviceId、identityToken。同用户＋同安装＋同平台实例返回已有会话（含已结束会话，用户再次发送会重新打开）；不同用户或安装不会互通。没有合法凭据不按邮箱合并。原 Key 改变后需要重新签发凭据。

Flutter 通过 `FastCatSupport(identityProvider: ...)` 或 `FastCatClient(identityProvider: ...)` 返回 `FastCatIdentityProof(deviceId: ..., token: ...)`；provider 在新建会话前调用。也可在 client.start 中显式传 deviceId／identityToken。网页通过宿主 visitor 对象传递同名字段。

退出业务账号时，宿主可调用 `client.revokeSession()` 撤销服务端凭据、诊断授权和待执行操作并清除本地会话；已执行但结果不明的修复保留待复查状态。同一用户设备之后凭新签名凭据可以恢复历史和新 token；与仅删除本地缓存的 reset 不同。不要在离线撤销失败时假定服务端已撤销。

## 明暗主题色

组件外观分别保存 themeColorLight、themeColorDark。明暗模式为 auto 时，网页跟随宿主主题／系统，Flutter 跟随宿主 ThemeData；强制 light／dark 时使用指定模式。两端及悬浮按钮保持同一规则。旧 themeColor 作为兼容回退；旧 SDK 在升级前仍只识别单色。

## 配置示例（宝塔环境变量）

```ini
# 本机 Nginx 反代时启用，并确保代理追加真实客户端 IP
TRUST_PROXY=loopback
API_RATE_PER_MINUTE=1200
UPLOAD_DAILY_MB=100
AI_QUEUE_LIMIT=100
# 留空使用数据库旁 backups 目录；如自定义请确保 www 用户可写
# BACKUP_DIR=/私有路径/support-backups
BACKUP_KEEP=7
# 与宿主后端共享的至少32字节随机密钥；不填则不启用签名复用
# VISITOR_IDENTITY_SECRET=由运维生成并安全保存
```
